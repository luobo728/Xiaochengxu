# 登录系统说明（姓名 + 手机号）

## 现在是什么状态

**本地模式**：登录校验在手机本地完成，**不需要云函数**，打开就能用。

**演示账号：姓名 `1`、手机号 `1`**（在「我的」页登录卡片上也有提示）。
登录后：显示账号卡片（姓名 + 手机号 + 登录时间），并解出「孩子档案」「课时与余额」；未登录时这两张卡片会隐藏。

> 本地模式的局限：换手机 / 清缓存需要重新登录，账号表也只在代码里（`utils/auth.js` 的 `LOCAL_USERS`）。
> 接入云函数后，账号放在云端 `users` 集合，谁在哪台手机登录都一致。

## 出现变化的地方

| 位置 | 未登录 | 已登录 |
| --- | --- | --- |
| 头图副标题 | 「未登录 · 请先登录」 | 「家长账号 · 已绑定 1 名幼儿」 |
| 「我的」顶部卡片 | 家长登录（姓名 / 手机号 / 登录按钮） | 账号卡片（姓名 / 手机号 / 登录时间 / 切换账号） |
| 孩子档案、课时与余额 | 隐藏 | 显示 |
| 底部「退出登录」 | 可见（点击后仍是未登录态） | 二次确认后退出 |

## 接口（5 个）

| 方法 | 说明 |
| --- | --- |
| `getUser()` | 同步，返回 `{ name, phone, role, token, loginAt, loginAtText }` 或 `null` |
| `isLoggedIn()` | 同步，布尔 |
| `login(name, phone)` | Promise → `{ ok, msg, user }`（姓名或手机号为空、或两者不匹配时 `ok=false`） |
| `logout()` | Promise → `{ ok: true }`，清掉本机登录状态 |
| `demoAccount()` | 同步 → `{ name: '1', phone: '1' }` |

数据层在 `utils/auth.js`，页面只调用这些方法（页面里没有写死的账号）。

## 以后切到云端（页面不用改）

1. 部署云函数 **`auth`**（`cloudfunctions/auth/`，右键 →「上传并部署：云端安装依赖」）
2. 在云开发控制台建集合 **`users`**，权限选「仅管理端可读写」（客户端不直接读它）
3. 往 `users` 里加一条家长账号：
   ```json
   { "name": "张三", "phone": "13800000000", "role": "家长", "enabled": true }
   ```
   `phone` 建议建索引（唯一）
4. 把 `utils/auth.js` 顶部的 `MODE` 改成 `'cloud'`

云函数的三个 action：

| action | 入参 | 返回 |
| --- | --- | --- |
| `login` | `{ name, phone }` | `{ ok, user, token }`（不匹配时 `ok:false` + 中文原因） |
| `me` | `{ token }` | `{ ok, user }`（用于校验登录是否还有效） |
| `logout` | `{ token }` | `{ ok }`（服务端把 token 作废） |

## 生产前必须做的两件事

1. **关掉开发账号**：给云函数 `auth` 加环境变量 `ALLOW_DEV_ACCOUNT=0`（之后 `1/1` 就登不进去了）
2. **加强登录安全性**：现在只用「姓名 + 手机号」两个值，属于弱凭据，适合内部试用。
   正式对外建议改成 **手机号 + 短信验证码**（或微信一键登录 `wx.getPhoneNumber`），
   服务端保存验证码/会话，并限制尝试次数。
