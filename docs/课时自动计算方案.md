## 2. 一句话方案

**老师点一次名 → 该到课的孩子各扣 1 课时 → 自动写进课时流水 → 家长端「课时」tab 和「账单明细」立刻变成真数据。**

课时就是钱，所以沿用计费模块已有的两条铁律（见 `docs/billing-api.md` 末尾）：

1. **所有课时增减只走一个口**（`utils/billing.js` 的新接口），页面不许自己改数字；
2. **余额永远由流水算出来**，不手工改数字。

## 3. 数据模型（本机三张"表"，都在 storage 里）

### ① 课表 lessons —— 本机 `schedule_lessons_v1`（云端集合 `lesson_schedules`）

| 字段 | 例子 | 说明 |
| --- | --- | --- |
| `id` | `L20260415A` | 一节课的唯一 id |
| `date` / `time` | `2026-04-15` / `09:20` | 上课日期与开始时间 |
| `name` | `主题课 · 春天的颜色` | 课程名 |
| `teacher` | `王老师` | 任课老师 |
| `cls` | `大一班` | 班级（和相册用同一套班级名，便于以后联动） |
| `studentIds` | `['lele','tian']` | 这节课该来的孩子 |
| `hours` | `1` | 这节课扣几课时（按次=1；按分钟=时长÷45） |
| `status` | `planned` / `settled` / `canceled` | 结算状态 |
| `cleared` | `true` / 没有 | 这一天被手动「清空点名」过：自动补算跳过它（配 `clearedAt` / `clearedBy`，见第 12 节） |

### ② 点名 marks —— 本机 `schedule_marks_v1`（云端集合 `attendance_marks`）

| 字段 | 例子 | 说明 |
| --- | --- | --- |
| `id` | `L20260415A:lele` | 课 + 孩子，**天然唯一**（判重就靠它） |
| `lessonId` / `studentId` | | |
| `status` | `present` 到课 / `leave` 请假 / `absent` 旷课 / `trial` 试听 | 老师标的 |
| `hours` | `1` | 这节实际该扣多少（请假 = 0） |
| `settledHours` | `1` | **已经真正记进流水的课时** —— 判重的主判据 |
| `settleCount` | `0` | 结算过几次（流水 ref = `id#次数`） |
| `saved` | `true` | 老师（或自动补算）标过没有：标过才显示「已结算」 |
| `by` / `at` / `timeText` | `王老师` / 时间戳 / `04-15 09:30` | 谁在什么时候标的（页面展示用） |

### ③ 流水 —— 复用现有账本 `billing_v1.ledger`

新增 `hour` 单位的两种类型（`pages/billing` 的图标表里 `consume` 早就预留好了，`refund` 补了一个「补」图标）：

| type | typeName | amount | note 例 |
| --- | --- | --- | --- |
| `consume` | 上课扣课时 | `-1` | `乐乐 · 主题课 · 春天的颜色 · 王老师（04-15 09:20）`（旷课再加 ` 旷课照扣`） |
| `refund` | 课时回补（纠正） | `+1` | `乐乐 这节不用扣（请假/试听/不算课时），回补 1 课时` |

并且给流水**加一个字段 `ref`** 用来判重 —— 实际值是 `mark.id + '#' + 结算次数`（例 `L20260415A:lele#0`）：同一次结算重复调用 → ref 相同，被判重挡掉；老师改了点名再保存 → 次数 +1，换新 ref，走冲正补差额。这是「绝不重复扣」和「改点法不丢历史」的关键。

## 4. 扣课时规则（默认值，仍然只写一处）

放在 `utils/billing.js` 顶部，和现有 `RULES` 挨着（项目里「规则只写一处」的约定）：

```js
// 上课扣课时规则（自动计算课时的唯一规则表）
const ATTEND = {
  perLesson: 1,        // 正常到课：扣 1 课时
  leaveFree: true,     // 请假：不扣
  absentCharge: true,  // 旷课：照扣（园所常见做法，可关）
  trialFree: true,     // 试听：不扣
  makeupFree: true,    // 补课：不额外扣
  unitMinutes: 45,     // 若按分钟计费：45 分钟 = 1 课时（用不到就不看这项）
  lowWarn: 4           // 剩余课时 ≤ 4 时提醒家长续费
}
```

课时扣成负数怎么办：**默认照扣**（课确实上了），同时给家长一条「课时不足」提醒；要改成"没课时不让上课"就把 `allowNegative` 打开（一并放进 `ATTEND`）。

## 5. 幂等：同一节课绝不重复扣

两道闸，都写在数据层（页面管不着）：

1. **主判据在点名记录里**：每条记录带 `settledHours`（已经真正记进流水的课时，以及 `saved` 有没有标过）。结算时先算 `delta = 目标课时 − settledHours`；`delta === 0` 直接返回「这节课已经记过了」，**一笔流水都不写**。
2. **兜底在账本里**：每笔流水带 `ref = mark.id + '#' + settleCount`（例 `L20260415A:lele#0`），`applyHours()` 写入前先查同一个 ref，**查到就跳过**（返回 `{ ok:false, dup:true, msg:'这笔已经记过了' }`）。

所以老师**重复点保存、断网重试、自动补算撞上老师点名**，都不会重复扣 —— 跟现有模块一个思路（券码看 `claims[code]`、打卡看 `checkins[date]`）。

- **纠正不改历史**：老师把某孩子从「旷课」改成「请假」，`settleCount` +1 → 换新 ref，走**冲正**（写一条 `refund` +1、note 写明原因），原来那条 `consume` 一条不删 —— 账能对得上，也符合真实园所财务习惯。
- **一节只结算一次状态**：老师点过保存后 `lesson.status` 立刻变 `settled`（哪怕这节一分课时都没扣），所以「自动补算」不会再回头碰它。
- **请假的孩子也留痕**：0 课时同样写一条点名记录（显示「已结算 · 不扣课时」，也算进「已结算 3/3 人」），下次进来还看得到「谁请假了」。
- 课时对账自检：`hoursStat().total === 账本里 hour 单位金额的合计`（`smoke_schedule.js` 里逐条对过；云端换成唯一索引 + 服务端校验）。

## 6. 三种触发方式（按可靠度排序）

| # | 触发 | 怎么工作 | 用在哪 |
| --- | --- | --- | --- |
| 1 | **老师点名（主）** | 老师端「点名」页：今天该上的课 → 名单默认全「到课」→ 点掉请假/旷课 → 「保存点名」→ 逐孩写流水 | 本机 + 云端都这样 |
| 2 | **打开页面自动补算（兜底）** | 进「课时」tab 或小程序回到前台时跑一次 `settleDue()`：把**时间已过、还没结算**的课按规则补上（默认全到课；已有点名记录的按记录） | 本机模式就靠它做出"自动"效果 |
| 3 | **家长签到（可选增强）** | 家长进园扫门口码 → 记一条「已到园」→ 老师点名时默认勾上，只复核异常 | 需要老师愿意用 |

> 本机模式没有后台定时器，所以「自动」的诚实做法就是第 2 条：**一进页面就把该扣的补上**。将来云端换成定时触发器（每天固定时间结算）调的是同一个函数，页面不用改。

## 10. 每个孩子各算各的（孩子档案接线，已实现）

> 起因：用户反馈「点个名同一个人扣了三节课时」—— 一节课点 3 个孩子，账本里出现 3 条**只写课程名、看不出是谁**的流水，看着像同一个人被扣 3 次。完整说明见 `docs/孩子档案.md`，这里只记「课时」这一侧改了什么。

**① 账本按孩子分格**（`utils/billing.js`）：从「一本设备账」改成 `kids: { [childId]: { hours, spent } }`，每个孩子各有一格；每笔流水带 `childId` / `childName`、说明文字也带上孩子名字 → 一节课 3 个孩子就是**三条能分清是谁**的记录。

- `applyHours({ amount, type, typeName, note, ref, childId, childName })`：带 `childId` 就记到那个孩子头上，不带就记设备账（兼容老数据）；
- `hoursStat(childId)` / `listLedger(limit, childId)` / `getSummary(childId)`：传 `childId` 就只算 / 只回这个孩子的；
- **`kidsStat(ids)`**：一次查多个孩子 → `[{ childId, left, spent, total }]`（点名页 / 课时页 / 档案页都用它）；
- 不传 `childId` 时仍是**全园合计**（设备账 + 所有孩子之和），老口径不变；
- `transferLegacy(childId, childName)`：把老版本留下的设备账**划给第一个孩子**（不写流水，只搬家）；
- `claimByCode(code, childId, childName)`：券码**一台设备只领一次**（判重键永远是券码本身），`childId` 只是给这笔流水贴个「算在谁头上」的标签。

**② 名单来自档案**（`utils/schedule.js`）：`roster()` → `children.list()`，`studentIds()` / `studentName(id)` 都读档案；`ensureLessons()` 开头跑 `syncRoster()`，把「今天起的待上课」的名单刷成最新档案（新建档的孩子马上能点名），**已结算 / 过去的课永不重写**。

**③ 点名只扣被点的那个孩子**：`saveMarks()` 返回 `{ ok, msg, charged, backed, chargedKids, backedKids }`；每笔流水 `ref = mark.id + '#' + settleCount`（例 `L20260415A:lele#0`）→「课 + 孩子」天然唯一，同一次结算重复调用必被挡。

**④ 演示课时**：`bootstrap()` 给**每个孩子各送 20**（`ref = demo_gift_v1:<孩子id>`，各判各的重，一辈子只送一次）；**一个档案都没有时不送**（改掉了「先给设备账送 20、等建档后又送一次 → 变 40」的老缺陷）。

**⑤ 页面**：`pages/children`（档案页）、`pages/children-edit`（建档页）新增；点名页人数 = `roster().length`，没档案时显示「去建档」卡片；课时页头图显示「哪个孩子 + 他自己的账」，右上角「切换孩子 ›」（家长端锁死不给切）；「我的」页孩子档案卡显示真实孩子 + 真实课时，**三列小统计只有老师端有**（家长端 `wx:if="{{showKidStats}}"` 整块不渲染）；档案详情页多了 **「＋3 课时（测试用）」** 按钮（只演示账号 + 有改档权限可见，点一次给这个孩子补 3 课时，专门用来试点名扣课时）；**券码领的课时也记到卡片上的孩子头上**（`claimByCode(code, childId, childName)`，不带 `childId` 会落进设备旧账）。

## 12. 清空点名（把「3/3」变回「0/3」＝没点名的状态，已实现）

老师点错了一整节（或者想整节课重来）：点名页顶上有一个「清空今日点名」按钮 —— 点完这一天点过名的孩子**全部回到「没点过名」**，页面上那节课从「已结算 3/3」变回「**0/3**」，和从来没点过一样。

一次做三件事（`schedule.clearDay(day, byName)`）：

1. **课回到 `planned`**：`status` 回 `planned`、`settledHours` 归零 → 页面 0/3、状态「待点名」，「清空」按钮自己消失（没点过名就不显示按钮）。
2. **已经扣掉的课时按「冲正」退回**：每个孩子一条 `refund` 流水（说明「<孩子> · 清空 <日期> 的点名，退回 N 课时（<老师> 手动清空）」）；**明细只增不删**，老账一行不动。
3. **课带上 `cleared` 标记**：进页面「自动补算」会跳过它 → 清完就是没点名，不会被系统又扣一遍（不然一刷新就白扣了）。字段：`cleared` / `clearedAt` / `clearedBy`。

**为什么是「把记录清零」而不是「删掉记录」**：判重键是 `mark.id + '#' + settleCount`，退回那笔用 `#clear<序号>`。要是把点名记录删了，下次重新点名会用回原来的 `#0`，和退回那笔撞号 → 判重失效、课时凭空多出来。所以：点名记录**留着但清零**（`status: 'present'` / `hours: 0` / `settledHours: 0` / `saved: false`），同时 `settleCount` **先走一格**，下次重扣是 `#<序号+1>` —— 退回那笔、重扣那笔、老账三方互不撞号。

谁点得动 / 什么时候出现：

| 情况 | 表现 |
| --- | --- |
| 老师三人组（李老师 / 王老师 / 陈老师） | 能点（`canRoll`）—— 普通老师也能清 |
| 家长端 | 一票否决：按钮不渲染、函数里也拦（`role.rollTip()`） |
| 看的是今天 | 文案「清空今日点名」 |
| 换到别的日子 | 文案「清空这一天点名」 |
| 这一天没点过名 | 按钮不显示；直接调也返回「这一天没有点过名，不用清」 |
| 有没保存的改动 | 先拦住：「有改动还没保存：先点「保存点名」再清空」 |
| 清完想重新点名 | 照常「保存点名」，按新的一笔扣（判重键各自独立） |

自检：`smoke_schedule.js` 第 16 节「清空点名：把「3/3」变回「0/3」」→ **285 项断言全通过**；变异测试 `mutations_clear.js` → **17 组全部被抓住**（含「退回写成倒扣」「清空标记不落盘（真机口径）」等），源码逐文件 md5 校验还原一致。

## 13. 课程管理（改 / 加 / 删「这一节课」，已实现）

课表里每节课原本是写死的演示数据（课程按日期轮换）。现在老师能自己**改 / 加 / 删**：

- **入口**：「我的 → 课程内容管理」（老师端三个档位都能进；家长端一票否决，只看到锁卡片）。
- **能改什么**：课程名（≤ 24 字）、老师（≤ 8 字）、每节几课时（1~9，页面摆成胶囊）、内容简介（≤ 60 字）。
- **改的是「这一节课」**：只动这一天这一节，别的日子、别的时段都不动（改错了不影响别人）。
- **内容简介会露脸**：点名页每节课下面多一行；课时页「本周课时」每行也多一行 —— 家长看得懂这节课教什么。

### 一条硬规则：点过名的课不让改课时数

课时数决定结算扣多少（课时=钱）。一节课**只要有人点过名**（`status = 'settled'` 或存在 `saved` 的点名记录），
课时数就锁住：想改先到点名页把这一天「清空今日点名」，解锁后再改。
课程名 / 老师 / 内容简介随时能改 —— 它们不碰账。

两道闸（页面拦一道、数据层再拦一道）：

1. **数据层**（`utils/schedule.js` 的 `updateLesson`）自己拦，页面绕过界面硬存也改不动；
2. **页面**（`pages/course-admin`）锁住时点课时胶囊只弹一句说明，不做任何改动。

### 加课 / 删课（老师自己排课）

课表平时是「按日期自动生成」的演示课表（昨天起 2 周，每天两节）。老师也能自己加一节、删一节：

- **加课**：页面右上角「＋ 添加课程」→ 选**上课日期**（只能选今天以后）+ **上课时间** → 填课程名 / 老师 / 每节几课时 / 内容简介 → 「添加课程」。
- **删课**：编辑区底部的「删除这一节课」，或课表里每行的「删除」（都会先弹确认框）。
- **删掉的课不会自己回来**：课表是自动生成的，所以删掉的 id 会记一笔（`schedule_removed_v1`），
  `ensureLessons()` 生成课表时跳过它们 —— 不然下次进页面被删的那节又冒出来了。

两条线不能碰（都写在数据层，页面绕不过去）：

1. **过去的课加不了**：`addLesson` 里 `startTs(date, time) <= Date.now()` 直接拒 ——
   过去的课会被「自动补算」当成上过的课，把所有人的课时都扣一遍；
2. **点过名的课删不了**：`removeLesson` 走的是和改课时数同一道闸（`lessonRolled`），
   提示「先到点名页把这一天『清空今日点名』」。清空之后就能删（账本里那笔退回流水留着，明细只增不删）。

加课也不会撞车：同一天同一时间已经有课会被拒（提示「这一天 16:00 已经有课了」）。

### 数据层接口

| 函数 / 常量 | 干什么 |
| --- | --- |
| `listLessons()` | 「课程内容管理」列表：演示课表里所有课（含 `dayText / statusText / hours / desc / hoursLocked`），按时间从早到晚 |
| `updateLesson(id, patch, byName)` | 改一节：`patch = { name, teacher, desc, hours }`；校验不过返回 `{ ok:false, msg }`（人话，页面直接弹） |
| `addLesson(patch, byName)` | 加一节：`patch = { date, time, name, teacher, desc, hours }`；id 自动排（`L+日期+A/B/C…`），名单取当前孩子档案 |
| `removeLesson(id, byName)` | 删一节：点过名的删不了；删掉的 id 记进 `schedule_removed_v1`，免得自动生成的课表又把它生回来 |
| `MAX_NAME` / `MAX_TEACHER` / `MAX_DESC` / `HOURS_CHOICES` | 上限与课时选项，页面直接用这一份，不各写一份 |

课表数据多了 `desc` 字段（内容简介）；老数据没有这个字段就按空处理（升级不丢课表）。

## 附：边界情况怎么处理

| 情况 | 处理 |
| --- | --- |
| 一节课 90 分钟 | `lesson.hours = 2`（按分钟模式自动算） |
| 课时不够 | 默认照扣成负数 + 提醒家长；可开「没课时不让上课」 |
| 老师点错了 | 改点名 → 走冲正流水（+1 回补），不删历史 |
| 整节课点错了（想当没点过） | **点名页 →「清空今日点名」**：课回到「没点过名」（3/3 → 0/3）、已扣课时按冲正退回、课带 `cleared` 标记不再被自动补算（见第 12 节） |
| 课取消 / 老师临时不来 | 数据层已支持：`lesson.status = 'canceled'` 不结算，点名页直接挡住（提示「这节课已取消，不结算课时」）；**界面上还没有「取消这节课」按钮**（P2.5 待补） |
| 补课 | 单独建一节补课（`hours` 按规则=0 或 1），或走 `refund` 回补 |
| 转班 / 退学 | 只影响课表里 `studentIds`；已扣的历史不动（余额是总额，不做跨月结转） |
| 课表谁来维护 | 本机演示：`utils/schedule.js` 里按周生成；云端：园所后台排课（以后再说） |
