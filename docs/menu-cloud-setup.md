# 今日食谱（图片展示）· 云开发部署说明

## 一、权限边界（设计目标）

| 端 | 能做什么 | 代码位置 |
| --- | --- | --- |
| 客户端（家长） | **只能加载并显示图片**、点击看大图；页面上没有上传 / 删除 / 保存 / 分享任何入口 | `pages/menu/menu.*`、`utils/menu.js` |
| 管理端（老师） | 上传、删除食谱图片；非管理员打开只能看到「没有管理权限」 | `pages/menu-admin/menu-admin.*`，入口在「我的」页（仅管理员可见） |
| 服务端 | **唯一的写入入口**，校验调用者 openid 是否在管理员白名单 | `cloudfunctions/menuAdmin` |

关键点：客户端对数据库是只读（集合安全规则 `read: true / write: false`），所有新增/删除都必须经过云函数，云函数里再校验一次管理员身份 —— 所以即使有人伪造请求也无法导入图片。

## 二、一次性配置（约 5 分钟）

### 1. 开通云开发
开发者工具顶部工具栏点「云开发」→ 开通 → 新建环境（免费额度足够）。

- 只有一个环境时：**什么都不用填**，代码默认使用默认环境。
- 有多个环境时：把目标环境 ID 填到 `utils/env.js` 的 `ENV_ID`（形如 `cloud1-0gxxxxxx`）。

### 2. 部署云函数
左侧资源管理器展开 `cloudfunctions/menuAdmin` → 右键 → **上传并部署：云端安装依赖** → 等提示部署成功。

### 3. 建两个集合（云开发控制台 → 数据库 → 新建集合）

| 集合 | 用途 | 权限（直接用控制台预设那一项，不用手写规则） |
| --- | --- | --- |
| `menu_photos` | 食谱图片记录 | **所有用户可读，仅管理端可写**（等价于安全规则 `{"read": true, "write": false}`） |
| `menu_admins` | 管理员名单（文档 ID = openid） | **仅管理端可读写**（等价于 `{"read": false, "write": false}`） |

这样客户端对 `menu_photos` 只能读，写入只能由云函数完成。

### 4. 云存储权限（云开发控制台 → 存储 → 权限设置）

选控制台预设 **「所有用户可读，仅创建者可读写」** 就够了：

- **读**：所有家长都能看到食谱图片；
- **写**：老师上传时创建的是自己的文件，符合「仅创建者可读写」；
- **删除**：走云函数（云函数以管理端身份运行，不受该规则限制）；
- 非管理员就算自己往存储里传了文件，也**写不进数据库**（`menu_photos` 客户端不可写），所以不会出现在任何页面上。

更严格一点（不想让任何陌生人都能往云存储里传文件）——改用「自定义安全规则」，填：

```json
{ "read": true, "write": "get(`database.menu_admins.${auth.openid}`) != null" }
```

> ⚠️ 用这条规则就必须同时用第 5 步的**方式 B**（把 openid 写进 `menu_admins`），否则管理员自己上传也会被判为无权限。

不要用 `{ "read": true, "write": "auth != null" }`：它等于「任何登录用户都能往存储里写、也能删别人的文件」，比上面两种都松。

### 5. 配置管理员（二选一）

- **方式 B（推荐）**：数据库 `menu_admins` 集合里新建一条记录，**文档 ID 直接填 openid**。它同时满足「写数据库」和「严格存储规则」两处校验。
- **方式 A**：云开发控制台 → 云函数 → `menuAdmin` → 配置 → 环境变量，新增 `ADMIN_OPENIDS`，值为你的 openid；多个管理员用英文逗号分隔。注意：这条只影响「能否写数据库」，如果第 4 步用了严格存储规则，仍然必须同时用方式 B。

**怎么拿自己的 openid？**（入口只对管理员显示，所以第一次要先拿到 openid）

1. **最简单**：打开小程序 →「我的」页 → **长按页面最底部的版本号那一行**（「阳光幼儿园 · 家长端 v1.0.0」）→ 弹窗显示当前 openid，点「复制」。
2. 云开发控制台 →「用户管理」（若你的控制台有这个入口）可看到访问过小程序的 openid，前提是 `wx.cloud.init({traceUser: true})` —— 本项目已开启。
3. 开发者工具 → 调试器 Console 执行：
   `wx.cloud.callFunction({ name: 'menuAdmin', data: { action: 'whoami' } }).then(r => console.log(r.result))`

拿到 openid 后按上面任一方式配置，然后**重新进入一次「我的」页**，「食谱管理」入口就会出现（该入口只对管理员渲染）。

### 6. 验证
「我的」→「食谱管理」→ 选日期、选餐次 → 上传 1~2 张图片 → 回到首页 → 点「今日食谱」→ 应能看到图片；点图片可全屏浏览。

## 三、数据结构（`menu_photos`）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `date` | string | `YYYY-MM-DD`，客户端按天查询 |
| `meal` | string | `breakfast` / `morning` / `lunch` / `afternoon` / `dinner`（早餐/早点/午餐/午点/晚餐） |
| `fileID` | string | 云存储文件 ID，`<image src>` 可直接渲染 |
| `sort` | number | 同餐次内的展示顺序（按上传时间递增） |
| `createTime` | date | 服务端时间 |
| `creator` | string | 上传者 openid |

餐次常量定义在 `utils/meal.js`，客户端与管理端共用；要改名称/时间只改这一个文件。

## 四、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 页面显示「尚未连接云开发」 | 未开通云开发，或多环境下 `utils/env.js` 的 `ENV_ID` 填错 |
| 管理端提示「已添加 N 张」但列表是空的、家长端也永远看不到 | 客户端读的环境和云函数部署的环境不是同一个：把 `utils/env.js` 的 `ENV_ID` 填成云函数所在环境的 ID（只有一个环境时留空即可）。这种情况 `cloudReady` 仍是 true，页面不会报「未连接云开发」，所以最容易踩 |
| 「食谱管理」一直提示没有管理权限 | 云函数没部署成功；或 openid 没写进 `ADMIN_OPENIDS` / `menu_admins`；改动环境变量后需重新进入页面 |
| 图片是空白框 | 存储权限的 read 不是「所有用户可读」，或该文件已被删除 |
| 上传报错 | 单张建议 2MB 以内；上传走微信压缩，超大图请先压缩 |
| 删除后家长端还看得到 | 家长端下拉刷新即可（客户端不做实时推送） |
| 换环境 / 换账号 | 环境 ID 改 `utils/env.js`，管理员白名单在新环境里重新配一次 |

## 五、以后想换成自建后端？

`utils/menu.js` 是**唯一**直接与云开发交互的文件，页面只依赖它导出的这几个函数：

```js
isCloudReady() / cloudError() / listByDate(date) / listByDates(dates) /
groupByMeal(rows, meals) / whoami() / addPhotos(items) / removePhoto(id) / previewUrls(fileIDs)
```

把这几个函数改成你后端的 HTTP 请求（`wx.request`）即可，所有页面无需改动。客户端仍然只做展示，写入接口建议同样在服务端校验管理员身份。
