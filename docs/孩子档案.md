# 孩子档案（建档 / 改档 / 删档）+ 课时按孩子独立计算

> 状态：**已实现**（数据层 `utils/children.js` + 档案页 `pages/children` + 建档页 `pages/children-edit` + 点名 / 课时按孩子分账）。
> 自检：`node smoke_children.js` → **277 项断言全通过**（含 27 组变异测试，全部被抓住）。
> 相关：`docs/课时自动计算方案.md`（课时自动计算）、`docs/billing-api.md`（计费数据层）、`utils/schedule.js`（课表 / 点名）、`utils/billing.js`（账本，唯一写入口 `applyHours`）、`utils/demo-role.js`（权限判断）。

## 1. 为什么要做这件事（用户反馈的那个 bug）

> 「怎么我点个名同一个人扣了三节课时？不同的孩子要独立出来。」

**根因**：最早的版本里，课时账是**按设备**记的（一本账），点名结算写流水时**只写课程名、不写孩子名**，几个孩子在同一节课的流水长得一模一样。
于是一节课点 3 个孩子 → 账本里出现 3 条「主题课 · 春天的颜色 · 王老师（04-15 09:20）」这种**看不出是谁**的记录，一眼看过去像是「同一个人被扣了 3 次」。

**修法**（两步一起做才彻底）：

1. **课时按孩子分账**：账本从「一本设备账」改成「每个孩子一本小账」（`kids: { [childId]: { hours, spent } }`），谁的课扣谁的，**互不牵连**；
2. **流水写清是谁**：每笔流水带 `childId` / `childName`，说明文字里也带上孩子名字（`乐乐 · 主题课 · 春天的颜色 · 王老师（04-15 09:20）`），明细列表里能一眼看出这笔是谁的。

**顺带修掉的第二个缺陷**：`bootstrap()` 在「一个档案都没有」时，以前会给**设备账**送 20 课时；等老师建好第一个档再进这一页时，那 20 会被划给第一个孩子（`transferLegacy`）、又按「每个孩子各送一份」再送一次 —— 同一个孩子白拿 40，跟别的孩子对不上。
现在：「没档案就不送课时」（课时页显示 0 + 一句「去建档」），建好档后**每个孩子各得 20**、一视同仁。`smoke_children.js` 第 3.1 条专门盯这一条。

## 2. 一句话方案

**先建档（谁是这个班的孩子）→ 点名时名单自动来自档案 → 每点一次名，只扣「被点的那个孩子」自己的课时，各算各的。**

不用手写名单，也不用「建档完之后再单独做一顿配置」：**新建档的孩子，下一次进点名页 / 课时页就自动进名单、自动拿到演示课时**（`syncRoster()` 会把「今天起的待上课」刷成最新名册）。

## 3. 三份数据各管一段（谁也不越界）

| 数据 | 存储 key | 文件 | 管什么 |
| --- | --- | --- | --- |
| **孩子档案** | `children_v1` | `utils/children.js` | 姓名 / 性别 / 生日 / 班级 / 家长姓名 / 家长手机 / 备注 |
| 演示种过没有 | `children_seeded_v1` | 同上 | 演示档案（乐乐 / 甜甜 / 木木）一辈子只种一次 |
| **课表 + 点名** | `schedule_lessons_v1` / `schedule_marks_v1` | `utils/schedule.js` | 谁该上哪节课、到底来没来 |
| **课时账本** | `billing_v1` | `utils/billing.js` | 每个孩子还剩几课时（按 `childId` 分格） |

`utils/children.js` **谁都不 require**（只读写两个 storage key），免得和 `billing.js` / `schedule.js` 绕成循环依赖。

| `createdAt` | 时间戳 | 建档时间 |

## 5. 建档时拦什么（校验都在数据层，页面只负责显示）

| 情况 | 提示 |
| --- | --- |
| 姓名为空 | `请填写孩子姓名` |
| 姓名 > 8 字 | `姓名最多 8 个字` |
| 班级不在名单里 | `班级要选：小班 / 中班 / 大班 / 大一班 / 学前班` |
| 性别不对 | `性别只能选：女 / 男` |
| 生日格式不对 | `生日要填成 2020-03-08 这样` |
| 生日是未来 | `生日不能是还没到的日期` |
| 手机号不是 11 位 | `家长手机号要填 11 位数字` |
| 备注 > 40 字 | `备注最多 40 个字` |
| **同班重名** | `「大一班」已经有个叫「乐乐」的孩子了，重名会点错人` |
| 一个班超过 30 个 | `一个班最多 30 个孩子，建不了更多了` |

**同班重名为什么必须拦**：点名时两个「乐乐」根本分不清谁是谁，扣课时一定会错。跨班重名不拦。

## 6. 数据层接口（`utils/children.js`，页面只调这些）

| 方法 | 说明 |
| --- | --- |
| `list()` | 档案列表（第一次调用会自动种演示档案，只种一次） |
| `read()` | 只读，不种演示档案 |
| `count()` / `ids()` | 人数 / id 数组 |
| `get(id)` / `byName(name)` / `nameOf(id)` | 按 id / 姓名查（`nameOf` 查不到就原样返回 id） |
| `defaultChildId(accId)` | 这个账号默认看哪个孩子（家长端 → 自己孩子；其他 → 第一个） |
| `pickerList()` | 切换孩子用的 `[{ id, name }]` 列表 |
| `avatarOf(child)` | 头像字（取姓名首字） |
| `subOf(child)` | 副标题「大一班 · 家长 乐乐妈妈 · 6 岁 5 个月」 |
| `ageText` / `sexText` / `phoneText(id)` | 年龄文案 / 性别 / 打码手机号 |
| `emptyForm()` | 新建档的空表单（班级默认 `大一班`、性别默认女） |
| `checkForm(form, editingId)` | 校验 → 错误文案（空串 = 通过） |
| **`save(form)`** | 建档 / 改档 → `{ ok, msg, child, created }`；`msg` = `档案已建立` / `档案已更新` |
| **`remove(id)`** | 删档 → `{ ok, child, msg }`；`msg` = `档案已删除（课时记录仍留在账单里）` / `没找到这个孩子的档案` |
| `OWNER` | 演示账号 ↔ 孩子对照（`{ parent: 'lele' }`） |

> **删档不删账**：档案删了，那个孩子的**历史课时流水仍然留在账本里**（`msg` 里也写明了）—— 财务记录不能因为删档案就消失。

## 7. 点名怎么连上档案（这是「独立计算」的关键）

改动都在 `utils/schedule.js`，页面几乎不用动：

| 步骤 | 做法 |
| --- | --- |
| 名单来源 | `roster()` → `children.list()`；`studentIds()` / `studentName(id)` 都读档案。**代码里不再写死名单** |
| 名册同步 | `ensureLessons()` 开头跑 `syncRoster()`：把**今天起的待上课**（`status === 'planned'` 且 `date >= 今天`）的 `studentIds` 刷成最新档案 —— 新建档的孩子马上能点名 |
| 不改历史 | 已结算 / 过去的课**永不重写**（`纠正不改历史`）：昨天那节课的名单就是你当时点的那几个孩子 |
| 点名结算 | `saveMarks(lessonId, [{ studentId, status }], byName)` → 逐个孩子算差额，**只扣这个孩子自己的**；返回 `{ ok, msg, charged, backed, chargedKids, backedKids }`（`msg` 形如 `已结算 1 人，扣 1 课时`） |
| 流水写明是谁 | 每笔流水带 `childId` / `childName`；`ref = mark.id + '#' + settleCount`（例 `L20260415A:lele#0`）→ **「课 + 孩子」天然唯一**，同一次结算重复调用必被挡；改了点名 = 换新 ref 走冲正 |
| 说明文字 | 扣课：`乐乐 · 主题课 · 春天的颜色 · 王老师（04-15 09:20）`（旷课再加 ` 旷课照扣`）；回补：`乐乐 这节不用扣（请假/试听/不算课时），回补 1 课时` |
| 演示课时 | `bootstrap()`：每个孩子各送 20，`ref = demo_gift_v1:<孩子id>`（各判各的重，一辈子只送一次）；**没档案就不送**（见第 1 节） |

**「同一个人扣三节」被两道闸彻底堵住**：

1. 账是**按孩子分格**的 —— 点乐乐只动 `kids['lele']`，甜甜 / 木木的余额、流水一动不动；
2. 流水 **ref 带孩子 id**、说明里带孩子名字 —— 哪怕列表挨在一起，也一眼看得出这是**三个不同孩子各扣 1 节**，不是一个人扣 3 节。

## 8. 页面（两个新页面 + 两处接线）

### ① 孩子档案页 `pages/children`

- 渐变头图（`#6E8BFF → #2E6BFF`）+ 上浮卡片；卡片头一行「共 N 个孩子 · 合计剩余 X 课时」；
- 每个孩子一行：头像字 / 姓名 / 副标题（班级 · 家长 · 年龄）/ 右侧 `余 N 课时`（≤ 4 显示为「课时偏低」的颜色）+ `已扣 N 课时`；
- **加课时入口（做明显点）**：演示账号 + 有改档权限时，名单**上面**多一条橙色提示条（`＋3 课时（测试用）` / 「点下面每个孩子右边的橙色按钮…」），**每一行右侧**也多一个橙色胶囊 `＋3 课时`（`catchtap="onAdd3"`，免得误触整行进详情）—— 点一下就给**这一行那个孩子**补 3 课时（走 `billing.applyHours`，**故意不写 `ref`** → 可重复点），toast `已给 甜甜 补 3 课时`，名单立刻刷新；家长端 / 普通老师 / 真账号都看不到，函数里再拦一道。
- 底部两个按钮：**「建立孩子档案」**（进 `pages/children-edit`）、**「去点名」**（进 `pages/attendance`）；
- 点某一行 → 有改档权限就进编辑页，没有就弹一句身份说明。

### ② 建立 / 编辑孩子档案页 `pages/children-edit`

- 表单：姓名（必填）→ 班级（picker）→ 性别（胶囊）→ 生日（picker，不能选未来）→ 家长姓名 → 家长手机号 → 备注（textarea）；
- 编辑老档时**最上面**先放一张橙色描边的课时卡：「这个孩子目前剩 N 课时，已经上掉 M 课时 —— **只算他自己的**，别的孩子扣多少都不影响这里」；
- 这张卡里是一个**大号橙色实心按钮** **「＋3 课时（测试用）」**（只在 `{{canEdit && demo}}` 时出现）：点一次给**这个孩子**补 3 课时 —— 走 `billing.applyHours({ amount: 3, type: 'gift', typeName: '补课时（测试）', childId, childName })`，**故意不写 `ref`** → 可以重复点，专门用来试「点名扣课时」；加完卡片上的数字立刻刷新（`refreshHours()`），提示 `已补 3 课时`；
- 保存 → toast `档案已建立` / `档案已更新` → 600ms 后返回档案页；
- 底部「删除这个孩子的档案」→ 二次确认 → toast `档案已删除（课时记录仍留在账单里）`（只有编辑老档时才有）。

### ③ 接线：点名页 `pages/attendance`

- 名单人数 = `schedule.roster().length`（不再是写死的）；
- **一个档案都没有时**：不显示空名单，改显示一张「先给孩子建档」的卡片 + 一个「去建档」按钮（`goChildren()` → `pages/children/children`），课时页此时显示 0。

### ④ 接线：课时页 `pages/course`

- 头图副标题：`乐乐 · 本学期共 N 课时 · 已完成 M 课时`（哪个孩子 + 他自己的账）；
- 右上角多一个「切换孩子 ›」（**2 个以上孩子**才出现）：点开动作面板选孩子，选中后**课时的总额 / 已完成 / 剩余 / 本周 / 明细全跟着换成那个孩子的**；
- **家长端不给切**（`kidLock`）：课时页锁在自己孩子身上，点「切换孩子」只弹一句「课时是你自己孩子的，只能看他一个」。

### ⑤ 接线：「我的」页孩子档案卡

- 卡片显示**真实档案里的孩子**（谁登录看谁：家长端看自己孩子，老师端看第一个），标签 `已建档` / `待建档`；
- 三个小数字也是真的：剩余课时（这个孩子的）/ 已上课时 / 在册孩子（`children.count()`）；
- 这三列小统计**只有老师端有**：家长端整块不渲染（`wx:if="{{showKidStats}}"`，值来自 `showKidStats: !role.isParent()`）—— 家长端看不到「在册孩子」这类全园数字，也就没得猜别人的账；
- 点卡片 → 进 `pages/children/children`。

## 9. 权限（判断只有一份：`utils/demo-role.js`）

| 谁 | 看档案 | 建档 / 改档 / 删档 | 点名 |
| --- | --- | --- | --- |
| 家长端 · 乐乐妈妈 | **只看自己孩子**（`OWNER.parent = 'lele'`） | ✗（点行 / 保存 / 删除全被拦，只弹说明） | ✗ 一票否决（`ROLL_PARENT_TIP`） |
| 老师端 · 李老师（超级管理员） | 全班 | ✓ | ✓ |
| 老师端 · 王老师（管理员） | 全班 | ✓ | ✓ |
| 老师端 · 陈老师（普通老师） | 全班 | ✗（`CHILD_STAFF_TIP`：建档 / 改档 / 删档由管理员负责） | ✓ |
| 真登录账号（非演示） | 走云端白名单（`notice.adminStatus()`） | 同上 | 同上 |

- `canEditChildren()`：超级管理员 / 管理员 → `true`；普通老师 / 家长 → `false`；非演示账号 → `null`（交给页面走云端白名单）。
- `canRoll()`：老师三档 → `true`；家长 → `false`；非演示账号 → `null`。
- 家长端在档案页是**只看**：`canEdit = false` 时页面显示锁提示，所有写操作（保存 / 删除）函数里**再拦一道**，直接进编辑页也改不动。
- **「＋3 课时（测试用）」按钮**：只给「有改档权限 **且** 是演示账号」（`{{canEdit && demo}}`）；家长端 / 普通老师连按钮都看不到，函数里**还再拦一道**（`CHILD_PARENT_TIP` / `CHILD_STAFF_TIP`）；真登录账号（非演示）整块不渲染，线上不会冒出来。名单页每行那个 `＋3 课时` 同理（`catchtap` + 同一个判断，函数里也再拦一道）。

## 10. 演示脚本（照这个点）

1. 「我的 → 切换演示账号」→ 选 **老师端 · 王老师**（管理员）→ 「我的 → 孩子档案」：看到乐乐 / 甜甜 / 木木三个档，卡片头「共 3 个孩子 · 合计剩余 60 课时」（每孩 20）。
2. 点 **「建立孩子档案」** → 填姓名「小满」→ 保存 → 回档案页，小满出现在列表里。
3. 「我的 → 点名」→ 选一节课：**小满已经在名单里**（新建档的孩子自动进名册）→ 只把小满点成「到课」→ 保存 → 提示「已结算 1 人，扣 1 课时」。
4. 回「孩子档案」：**只有小满的「已扣」变成 1、剩余少 1**；乐乐 / 甜甜 / 木木一分没动 —— 这就证明「每个孩子各算各的」。
5. 「我的 → 账单明细」：能看到「小满 · 主题课 · … · 王老师（…）」这一条 —— 说明文字里带着孩子名字，不会看成一堆一样的记录。
6. 点乐乐那行 → 编辑页顶部写着「这个孩子目前剩 20 课时…只算他自己的」→ 故意点「删除这个孩子的档案」→ 确认 → 提示「档案已删除（课时记录仍留在账单里）」→ 档案没了，但账单里乐乐的历史流水**还在**。
7. 「切换演示账号」→ 选 **家长端 · 乐乐妈妈** → 「孩子档案」：**只看得到乐乐一个**；点行 / 想改都被拦（一句身份说明）；「课时」页锁在乐乐身上、不给切孩子；「点名」进不去（锁卡片）。
8. 「切换演示账号」→ 回 **老师端 · 王老师** → 「孩子档案」→ 点 **乐乐** → 详情页点两下 **「＋3 课时（测试用）」**：卡片上的剩余课时 20 → 23 → 26，账单明细里多出两条「补课时（测试）」；再去「点名」把乐乐点成「到课」→ 回详情页 26 变 25 —— 这就是「先把课时补够再试点名扣课时」的路子。
9. 家长端再确认两件事：①「我的」页孩子档案卡上**没有**「剩余课时 / 已上课时 / 在册孩子」这三列小统计（只有老师端有，见 §8 ⑤）；②家长端点「扫码领课时」输入 `NEW-2026`，领到的 2 课时**记在乐乐头上**（不再落进设备大锅饭），「课时」页立刻能看到。

## 13. 边界情况

| 情况 | 处理 |
| --- | --- |
| 新建档的孩子还没进名单 | 进一次点名页 / 课时页就行：`syncRoster()` 会把今天起的待上课刷成最新名册 |
| 想让孩子今天就上课 | 建档 → 点名页选今天那节 → 名单里已经有了 |
| 转班 | 改档案里的班级即可；已扣的历史不动 |
| 删档 | 档案删、**历史流水留**（财务记录不消失）；该孩子的课时格留着 |
| 两个同班孩子重名 | 建档时就拦住（`重名会点错人`） |
| 家长想改孩子资料 | 家长端只能看；改由老师（管理员）来做 |
| 课时不够 | 默认照扣成负数 + 点名页提醒续费（口径见 `docs/课时自动计算方案.md`） |
